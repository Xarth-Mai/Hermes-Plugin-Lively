该仓库的访问权限由其所有者控制。这里只记录设计对照，不附带其源码、素材或聊天数据。

| 已核查来源（仓库内路径） | Lively 的处理 |
| --- | --- |
| `runtime/hermes/plugins/nianyu-process-scope/prompts/cognition.md`、`core.md` | 沿用 SOUL 定义身份、独立观点、按社交意图控制深度、准确处理短回应和反馈范围；区分尝试、发送、送达。精简重写行为提示，不接管 Hermes 的 Memory 策略。 |
| 同目录 `proactive.md` | 问候、好奇、观察或感受即可构成表达动机；不要求实用新信息；不强制提问；未回应不代表已读或忽略；日期和共同经历必须有记录依据；无合适表达可以静默。重写入主动联系 Skill。 |
| 同目录 `weixin.md` | 采用原生 MEDIA 路径、避免对未知结果自动重发。其换行拆气泡约定不迁移：固定 Hermes 基线默认保持单条消息，除非用户另行配置。 |
| `runtime/hermes/plugins/nianyu-process-scope/skills/sticker-gallery/SKILL.md` | 采用按需检索、场景与社交含义优先、通常每回合一图、关注反馈、不过度重复；不复用 293 张图库、不复制固定部署路径及平台转换产物。 |
| `docs/implemented/natural-proactive-contact.md` | 采用“机会不是必须发送”、尝试消耗预算、可信用户回应过滤、绑定版本失效、未知投递不冒充成功等思路。保留附件选定的更保守频率，不移植 Rust 调度、多租户、账务、近期窗口或跨渠道投递。 |

具体差异：NianYu 的文档描述了发送前再次复核和独立发送预算；Lively 使用原生 Cron
最终回复投递，目前只保证预检与原子机会领取，不能承诺发送前消除新消息竞态。
Lively 的未回应计数按“已放行机会”计算，包括静默和失败，不能称作已送达未回应消息数。

代码仍为本仓库独立实现，四张示例均由本仓库绘制。行为原则的参考不意味着已经复现
NianYu 的真实微信体验；本仓库的微信实机验收另见 `docs/validation.md`。
